## 3. 新增 API

- `POST /api/admin/retention/preview`
  - 权限：仅 `ADMIN`
  - 入参：可选 `{"retention_days": N}`；不传时使用全局 `ARTIFACT_RETENTION_DAYS`
  - 行为：只读，不删除文件、不删除数据库记录
- `POST /api/admin/retention/apply`
  - 权限：仅 `ADMIN`
  - 入参：可选 `{"retention_days": N}`；不传时使用全局配置
  - 行为：重新计算保护关系后安全删除，并写入 `retention_jobs` 审计记录
- `retention_days <= 0` 返回 `400`；未认证返回 `401`；`TESTER` / `VIEWER` 返回 `403`。

## 4. Retention Policy

- 第一版采用全局保留天数，环境变量：`ARTIFACT_RETENTION_DAYS`。
- 默认值：`30` 天，保守策略。
- 计算方式：`cutoff = now - N days`。
- 判定依据：`ExecutionRun.finished_at < cutoff`，只使用 `finished_at`，不使用 `Artifact.created_at`。
- 只有终态 Run 才允许进入候选：`PASSED`、`FAILED`、`PARTIAL`、`CANCELLED`、`ERROR`。
- `QUEUED`、`RUNNING`、`CANCELLING` 绝对不进入删除候选。
- 未创建 Project / Run / Artifact 三套配置，未引入自动调度器。

## 5. Preview 行为

- 只读操作，不删除任何物理文件，不删除任何数据库记录。
- 返回：`retention_days`、`cutoff`、`candidate_artifact_count`、`candidate_path_count`、`estimated_bytes`、`protected_artifact_count`、`protected_run_count`、`duplicate_path_count`。
- 同时返回最多 5 条候选 Artifact 和 Run 样本。
- `estimated_bytes` 只统计“该路径的所有引用都已进入候选、路径合法且当前是文件”的路径。
- 文件已缺失的候选路径不会计入 `estimated_bytes`。
- `duplicate_path_count` 统计候选路径中数据库引用数大于 1 的路径数。

## 6. Apply 行为

- Apply 对每一行重新检查 Run 状态、`finished_at`、保护关系，不信任旧的 Preview。
- 写审计表 `retention_jobs`，记录执行人、执行时间、保留天数、cutoff、Preview 预估、实际删除、失败和释放字节数。
- 返回 `job_id`、各类计数、`status` 和错误摘要。
- 状态规则：无失败为 `COMPLETED`；有成功也有失败为 `PARTIAL`；有候选但全部失败为 `FAILED`。
- 只删除 `Artifact`，不删除 Run / CaseResult / CaseResultAttempt / StepResult / FailureGroup / FailureOccurrence / Alert / NotificationLog。

## 7. 保护规则

- 正在执行的 Run：`QUEUED`、`RUNNING`、`CANCELLING`。
- `ACTIVE Alert` 关联的 `run_id`、`latest_run_id`、`reverify_run_id`。
- `OPEN FailureGroup` 的 `latest_run_id`。
- `REVERIFY` 中 Run 通过活动 Alert 的 `reverify_run_id` 得到保护。
- 只要 Artifact 的 `run_id` 命中保护集合，该 Artifact 就保留。

## 8. 重复 path 处理

- 使用 `Artifact.path` 精确匹配统计剩余引用数。
- 如果删除前还有其他 `Artifact.path == 当前 path` 的记录，则只删除当前 Artifact 数据库记录，保留物理文件。
- 只有当前 Artifact 是该 path 的最后一个引用时，才删除物理文件。

## 9. 文件删除失败处理

- `FileNotFoundError`：视为物理文件已满足清理结果，删除 DB 记录，并计入 `missing_file_count`。
- `PermissionError` / 其他 `OSError`：计为失败，保留 DB 记录，保留文件，`failed_count + 1`。
- 路径越界或路径指向目录：计为失败，保留 DB 记录。

## 10. DB 删除失败处理

- DB 删除由 `db.delete(artifact)` 后立即 `commit` 完成。
- 捕获 `SQLAlchemyError` 后执行 `rollback`，计为失败，保留该 DB 记录。
- 非最后引用场景：DB 删除失败时物理文件尚未被触碰，仍保留。
- 最后引用场景：必须先删物理文件再删 DB，以避免留下指向已删文件的其他引用；因此极少数情况下若物理文件已删成功、随后 DB 删除失败，会留下“文件已删除但 DB Artifact 仍存在”的可见残留。

## 11. 并发处理

- Apply 阶段逐行重新读取当前 Run，并重新计算保护 Run ID 集合。
- 已覆盖并测试：Preview 后 Run 状态变化、Preview 后创建 Reverify、Preview 后 Alert 状态变化、Preview 后 OPEN FailureGroup 变化。
- 当前第一版没有分布式锁；并发写窗口由“Apply 重新检查”兜底。

## 18. 遗留风险

- PostgreSQL 尚未实测，必须保持 `NOT VERIFIED`。
- 最后引用场景下，若物理文件删除成功但 DB 删除失败，可能出现物理文件已消失、DB Artifact 仍存在的罕见残留。
- `_protected_run_ids()` 当前在 Apply 逐行重新查询，正确性优先；数据规模很大时可能变慢，后续可优化为按批次缓存。
- 本地持久 SQLite 库已含大量历史受保护 Run/Artifact，实时 Preview 的保护计数较大，与本次合成候选无业务关联。
- 路径引用计数依赖数据库 `Artifact.path` 的精确字符串相等；如果历史数据存在同一物理文件的多种路径拼写混用，引用计数可能低估。
