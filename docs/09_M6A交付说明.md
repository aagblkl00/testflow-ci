# M6-A 交付说明：Artifact / Storage 安全加固

## 1. 修改文件列表

- `backend/app/main.py`：移除 `app.mount("/storage", ...)` 静态目录暴露。
- `frontend/vite.config.ts`：移除 `/storage` 开发代理。
- `backend/app/utils/artifact_signing.py`：新增 HMAC-SHA256 短时签名工具。
- `backend/app/config.py`：新增 `ARTIFACT_URL_TTL_SECONDS` 配置。
- `backend/app/api/runs.py`：新增 `GET /api/artifacts/{artifact_id}/content`，并切换所有 `artifact.url` 生成方式。
- `.env.example`：新增 `ARTIFACT_URL_TTL_SECONDS=300`。
- `scripts/selftest_m1.py`：将截图访问断言切换为签名 Artifact URL。
- `scripts/selftest_m2.py`：将视频与证据访问断言切换为签名 Artifact URL。
- `tests/test_m6_artifact_security.py`：新增 M6-A 专项安全测试。

## 2. API 变化

- 删除：匿名静态路径 `/storage/**`。
- 新增：`GET /api/artifacts/{artifact_id}/content`
  - 查询参数：`disposition=inline|attachment`、`exp`、`sig`。
  - 支持 Bearer 鉴权或短时签名访问。
  - 始终按 `artifact_id` 查库，不接受客户端传入物理路径。
  - 对 `Artifact.path` 做 `resolve()` 与 `relative_to(storage_dir.resolve())` 校验。
  - Artifact 不存在返回 404；文件已不存在返回 410；路径越界返回 403。
- `GET /api/artifacts/{artifact_id}/download` 继续保留，并复用路径校验。

## 3. 前端变化

- `frontend/src/pages/RunDetail.tsx` 未改调用方式，仍使用后端返回的 `artifact.url`。
- `<img>`、`<video>`、`<a href>` 现在直接使用短时签名 URL，无需携带 Bearer Header。

## 4. 安全机制

- 使用现有 `TESTFLOW_SECRET` 做 HMAC-SHA256 签名。
- 签名绑定 `artifact_id`、`disposition`、`exp`。
- 默认有效期 300 秒，可由 `ARTIFACT_URL_TTL_SECONDS` 配置。
- 不把 JWT 放入 URL。
- 即使签名合法，仍会按 Artifact ID 查库并校验实际文件路径，防止伪造或路径穿越。

## 5. 兼容性说明

- 数据库 `Artifact.path` 历史值保持不变，不迁移旧路径。
- 对外字段仍为 `artifact.url`，前端不产生 Breaking Change。
- 旧的 `/storage/**` 访问被彻底关闭。
- `video` 内容保留 Range 请求支持，`<video>` 可继续播放。
- 当前未引入多租户或复杂 RBAC。

## 10. 遗留风险

- `Artifact.path` 仍通过已鉴权的 list/get API 返回给登录用户，属于内部磁盘路径信息暴露；当前按兼容性要求保留，后续若需收紧可在不破坏前端的前提下从序列化层隐藏。
- 前端若长时间缓存 `artifact.url`，签名过期后需要重新拉取 Artifact 列表获取新 URL；当前页面为请求后立即渲染，未见实际问题。
- 前端构建仍有大 chunk 警告，属于既有体积问题，不在本轮范围。
